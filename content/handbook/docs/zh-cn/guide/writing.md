# 写作约定

## 侧边栏是自动生成的

配置在加载时扫描 `content/<slug>/docs/zh-cn/`，规则很朴素：

| 位置 | 结果 |
| --- | --- |
| 某一级的 `index.md` | 成为该分组的标题与链接，标题取自文件的一级标题 |
| 子目录 | 成为一个分组，名字来自它的 `index.md`，没有就退回目录名 |
| 其余 `.md` | 成为分组内的条目，文案取自文件的一级标题 |
| 顶层零散 `.md` | 归到「概览」分组 |

所以**一级标题要写清楚**：它同时是页面标题和侧边栏文案。改标题就等于改菜单，不用再改第二处。

## 排序

默认按文件名排，`index.md` 永远在最前。想调整顺序就在 frontmatter 里加数字：

```md
---
order: 2
---

# 标题
```

数字小的在前，没写 `order` 的排在最后。分组顺序同样看各自 `index.md` 的 `order`。

## 链接

- 站内跳转用相对路径：`[写作约定](./writing.md)`，VitePress 会按目录关系算出 URL，页面搬家也不会断。
- 不要在 Markdown 里写 `<http://localhost:5173/...>` 形式的自动链接，构建时的死链检查会判它无效；用行内代码表示地址。
- 指向站外的链接直接写完整 URL。

## 图片与静态资源

放 `public/` 下，用 `/xxx.png` 引用。`dist/assets/` 里的哈希文件名不要手工引用。

## 代码块

正常围栏代码块即可。需要行内高亮时用 `js{1,3}` 这类语法，VitePress 自带支持。
