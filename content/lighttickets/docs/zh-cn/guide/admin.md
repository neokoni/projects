# 管理后台

管理后台位于 `/admin`，仅 `admin` 角色可进入（非 admin 会被重定向回议题列表）。左侧导航固定为 12 个页面：标签、服务器、模板、玩家组、用户、设置、邮件、Turnstile、限流策略、外部登录、存储、关于。接口清单见 [管理 API](../api/admin.md)。

## 站点设置（`/admin/settings`）

| 配置项 | 作用 | 风险提示 |
| --- | --- | --- |
| 站点名称 | 页面标题、邮件抬头、页脚等处显示的站点名 | 留空会回退到内置名称 |
| 站点地址 `siteUrl` | 生成邮件链接、Minecraft 注册链接、外部登录回跳的基准地址 | 必须是不含路径、查询与片段的 `http(s)` origin；填错会让邮件链接与注册链接指向错误地址 |
| 默认语言 `defaultLanguage` | 平台默认语言，也是新访客与全部邮件的语言 | 改动会影响后续所有通知邮件的语言 |
| 页脚自定义内容 | 支持 Markdown，可用于备案号、版权声明 | 内容会对所有页面公开渲染 |
| 站点图标 / 站点 Logo | 分浅色与暗色两套，支持 PNG、JPEG、WebP、GIF、SVG，单文件最大 2 MiB | 暗色模式优先用暗色版本，未上传时回退到浅色版本，再回退到内置图标 |
| 要求登录查看议题 `requireLogin` | 开启后未登录用户无法查看议题列表与详情 | 同时会影响游戏内匿名视角，玩家必须先绑定 |
| 允许网页注册 `allowWebRegister` | 关闭后登录页隐藏注册入口且注册接口拒绝请求 | 也会阻止外部登录创建新账户 |
| 允许 Minecraft 注册 `allowMcRegister` | 关闭后游戏内 `/lit register` 无法生成注册链接 | 已有账户的玩家仍可用 `/lit bind` |
| 发送议题邮件通知 `sendEmailNotifications` | 开启后评论、状态变更、指派会发邮件 | 需要先配置可用的 SMTP |

站点地址还决定「密码重置」「邮箱更换」是否可用：只有 HTTPS origin 才能发送这两类邮件，否则相关入口会直接报错。

## 模板管理（`/admin/templates`）

模板决定创建议题时的表单、默认标签、默认受理人与完成钩子。编辑页分四段：

- 基础信息：模板 Key（创建后不可修改）、显示名称、描述、标题前缀、默认可见性、是否启用、默认受理人、议题标签。
- 表单字段：可添加单行文本、多行文本、Markdown、下拉选择、选择或输入、复选框、玩家选择；字段可设必填与描述，支持拖拽排序。字段语义见 [模板字段](../template/fields.md)。
- 完成钩子：为 `closed`（议题关闭）与 `invalid`（议题无效）两类事件配置动作，动作类型包括服务器命令、MiniMessage 与人工决策；人工决策可自定义决策字段、标题、提交后动作与结果卡片可见性。
- 编辑原文：直接维护模板 YAML，与图形编辑实时同步，以最后修改的内容为准。

默认可见性 `hidden` 有三个取值：

| 取值 | 行为 |
| --- | --- |
| 始终公开（`false`） | 新议题默认所有人可见，创建者不能改 |
| 始终隐藏（`true`） | 新议题只有发起者与管理组可见 |
| 由创建者选择（`optional`） | 创建流程会强制询问可见性，未选择则拒绝提交 |

首次初始化时平台会把随附的默认模板释放到数据目录（`bug_report`、`report`、`suggestion`、`permission_request`、`full_example`），之后它们与自建模板完全等价。停用模板（`enabled: false`）后它不再出现在创建页，也不能用于创建议题，但历史议题不受影响；删除模板同样不影响已创建的议题，历史议题仍保留原模板 Key 与表单数据。

## 标签、玩家组与用户

### 标签（`/admin/labels`）

每个标签有唯一标识符（只能包含字母、数字、下划线与短横线，最长 50，创建后不可修改）、显示名称（最长 50）、颜色（`#RRGGBB`）与说明。标签用于议题分类与列表筛选（`labelId`），模板可以引用标签实现自动打标。

### 玩家组（`/admin/player-groups`）

玩家组是模板「玩家选择」字段的候选来源，也是完成钩子里玩家选择字段的候选来源。

- 组 ID 只能包含字母、数字、下划线与短横线，长度 1~64。
- 可以在页面里手动添加成员（空格或逗号分隔多个玩家名）、重命名成员、移除成员；玩家名须为 3~16 位字母、数字或下划线。
- 插件也可以自动上传成员：在插件 `config.yml` 的 `playerGroupUpload` 中开启并填写组 ID，玩家进服时会把名字写入对应组。
- 删除组前请确认没有模板或完成钩子仍在引用它，否则相关字段会因「group 不存在」而校验失败。

### 用户（`/admin/users`）

用户列表按注册时间倒序展示，管理员可以：

- 调整角色（player / staff / admin）。角色变更会提升该用户的 `tokenEpoch` 并吊销其全部刷新会话，用户需要重新登录，权限即时生效。
- 删除用户。这是软删除：邮箱、密码、用户名、MC 绑定、头像都会被清空并打上 `deletedAt`，同时吊销其全部会话；历史议题、评论仍保留但作者显示为已删除账户。
- 不能删除自己。

## 服务器与 API Key（`/admin/servers`）

服务器是议题来源与插件身份的基础。每台服务器有：

- 服务器 ID：平台内唯一，只能含字母、数字、点、下划线与短横线，最长 64。
- 识别 ID：用于匹配 Velocity 插件上报的服务器名，可含中文等可打印字符但不能有控制字符；留空时回退为服务器 ID。
- 别称、地址、描述：仅用于展示与筛选。

API Key 与服务器分离管理，有两种类型：

| 类型 | 绑定范围 | 用途 |
| --- | --- | --- |
| Paper / Folia | 必须且只能绑定 1 台服务器 | 单机直连，插件不需要上报 `serverId` |
| Velocity | 可授权多台服务器 | 代理端每一台后端服务器共用同一 Key，靠请求里的 `serverId` 区分 |

操作与影响：

- 新建 Key 时明文只显示一次，请立即保存到插件的 `serverKey` 配置里。
- 「重新生成 Key」会让旧 Key 立即失效，所有使用它的服务器插件会掉线并持续 401，必须同步更新插件配置。
- 编辑 Key 的授权服务器列表会立即改变它能访问的服务器范围，Velocity 场景下未授权的服务器会收到 401 错误。
- 删除 Key 会让绑定的服务器与平台彻底断联；服务器仍被 Key 绑定时不能删除服务器本身，需要先处理 Key。
- 识别 ID 在同一平台内不能重复，否则报「识别 ID 已被其他服务器使用」。

## 存储（`/admin/storage`）

存储页分两部分：附件存储与 pending 附件策略。

存储驱动：

| 字段 | 说明 |
| --- | --- |
| `driver` | `local`（本地目录）或 `s3`（S3 兼容对象存储） |
| `uploadDir` | 本地驱动使用的相对目录，默认 `data/uploads` |
| `s3.endpoint` / `region` / `bucket` | 服务端点、区域与桶名 |
| `s3.accessKeyId` / `secretAccessKey` | 凭据；密钥留空表示保持原值 |
| `s3.forcePathStyle` | 兼容 MinIO 等需要 path-style 的服务 |
| `s3.presignExpiry` | 预签名链接有效期 |

「测试连接」请求的是**已保存**的 S3 配置（`HeadBucket`），不会读取表单里尚未保存的改动，所以要先保存再测试；驱动为 `local` 时会直接返回 `尚未配置 S3 存储后端`。切换驱动后新旧附件各按自己记录的类型读取，但改动本地目录或桶配置会影响全部同类型附件。

pending 附件策略：

- `pendingQuotaMiB`：单个用户未关联附件总配额，默认 50 MiB。
- `pendingExpirationEnabled`：是否让未关联附件自动过期，默认开启。
- `pendingTtlDays`：过期天数，默认 7 天。

## 邮件（`/admin/mail`）

SMTP 字段：启用邮件服务、SMTP 主机、端口、是否使用 SSL/TLS（通常 465 开、587 关）、用户名、密码（留空保持不变）、发件名称、发件邮箱，并提供「测试 SMTP 连接」。

启用邮件服务后会发生三件事：网页注册必须通过邮箱验证码、密码重置可用（还需 HTTPS 站点地址）、邮箱更换可用。关闭后这些功能一并停用。

## Turnstile（`/admin/turnstile`）

配置 Cloudflare Turnstile 的 Site Key 与 Secret Key（留空表示保持原值）。开启后注册、登录、申请密码重置、外部登录注册都要先通过人机验证；启用时必须同时填写两个 Key。

## 限流策略（`/admin/rate-limit`）

| 规则 | 默认值 | 说明 |
| --- | --- | --- |
| 全局请求限流 | 60 秒 / 100 次 | 所有 API 请求，含健康检查与预检，按 IP 计 |
| 认证接口限流 | 60 秒 / 10 次 | 登录、注册、刷新令牌、外部登录等，按 IP 计 |
| 邮件发送冷却 | 60 秒 | 注册验证码与密码重置共用，分别按邮箱或用户统计 |
| Minecraft 绑定保护 | 5 次失败 / 锁定 15 分钟 | 连续输错绑定码后的锁定策略 |

超限时接口返回 429 并带上 `Retry-After`。修改后立即生效；请求类规则的窗口或额度一旦变化，已有计数会整体清空重新开始。

## 外部登录（`/admin/federatedauth`）

配置通用的 OIDC 与 OAuth 2.0 Provider：路径标识 `slug`、显示名称、图标、协议、issuer、授权/token/用户信息端点、回调地址、Client ID/Secret、scope、各字段的 JSON Path、额外授权参数、PKCE、Client Secret 传递方式、启用状态与是否允许创建账户。

- OIDC 必须填 issuer 且 scope 包含 `openid`；OAuth 2.0 必须填全三个端点。
- 密钥加密存储，编辑时留空表示保持现有密钥；页面提供「测试 Provider」检查配置可访问。
- 删除 Provider 前必须先解除所有身份绑定，否则会被拒绝。可以「一键解绑全部」某 Provider 的身份，账户与数据保留。
- 关闭「允许创建账户」后，未绑定过的用户无法通过该 Provider 注册，只能绑定已有账户。

## 审计、完成钩子投递与关于

- 审计日志按议题记录，展示在议题详情的时间线里（能看见议题的人都能看到），涵盖状态变更、标题/正文修改、可见性变更、标签增删、受理人变更、评论编辑与完成钩子相关动作。标题与正文类的连续修改会在约 15 秒内合并成一条记录。
- 完成钩子的决策记录与命令执行结果展示在议题详情页，仅 staff/admin 可见；投递失败的命令会进入死信队列，重试接口为 `POST /api/admin/minecraft-hook-deliveries/:id/retry`，当前后台没有单独的页面入口。
- 关于页展示平台名称、构建版本、提交号与 GitHub 仓库地址，便于反馈问题时附上版本信息。
