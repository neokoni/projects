# 评论与附件

评论是议题的主要沟通渠道，附件用来补充截图与日志。两者都由议题的可见性约束，权限也各自独立。

## 评论

### 发表

- 网页：议题详情页底部的评论框，`POST /api/tickets/:id/comments`，请求体只有 `body`（不能为空）。需要登录，并且必须能看见该议题（隐藏议题只有作者与管理组能评论）。
- 游戏内：`/lit ticket comment <id>`，走 Minecraft 会话接口，评论来源记为 `minecraft`，界面上会给这类评论加一个 `MC` 标记。

评论框支持直接粘贴、拖拽或选择文件，文件先上传再替换为附件链接；提交按钮旁边还有「评论并关闭」「评论并已完成关闭」「评论并重新打开」，可以在发评论的同时切换状态。

### Markdown 渲染

正文与评论都走同一个渲染器（基于 `markdown-it`），支持的语法范围：

| 语法 | 是否支持 | 说明 |
| --- | --- | --- |
| 标题、段落、加粗、斜体、删除线 | 支持 | 标准 Markdown |
| 有序 / 无序列表 | 支持 | — |
| 任务列表 | 支持 | `- [x]` 渲染为只读复选框，不可点击 |
| 表格 | 支持 | 表格语法按默认规则渲染 |
| 围栏代码块与行内代码 | 支持 | 等宽字体展示，代码块右上角有复制按钮；不做语法高亮 |
| 图片 | 支持 | 常用 `![](/api/attachments/<id>)` 形式嵌入已上传的附件 |
| 链接 | 支持 | 裸链接自动识别；链接一律在新标签页打开并带 `rel="noopener noreferrer"` |
| 原始 HTML | 不支持 | HTML 被关闭，标签会作为文本转义输出，不会执行 |

单个换行即换行显示（`breaks` 默认开启），多行文本会按输入的行数原样渲染；渲染结果不含脚本与内联事件。

### 回复

- 网页：评论上的「引用回复」会把被回复内容以 `>` 引用块插入编辑框。
- 游戏内：`/lit ticket comment <id> reply <index>`，其中 `index` 是该议题当前评论列表里的下标（从 0 开始），提交时插件会生成 `> 原文` 引用块再加正文。

### 编辑与删除

| 操作 | 谁可以 | 说明 |
| --- | --- | --- |
| 编辑评论正文 | 仅评论作者 | `PATCH /api/tickets/:id/comments/:commentId/body`，管理组也不能改他人评论（`无权操作此评论`） |
| 删除评论 | 评论作者，或 staff/admin | `DELETE /api/tickets/:id/comments/:commentId`（`无权删除此评论`） |

编辑记录会写入审计（`comment_edit`），时间线上显示为「编辑了评论」，并可展开查看变更前后内容。删除评论会先清理挂在该评论上的附件；若附件清理失败或仍在清理中，接口返回 403 `评论附件仍在清理中，请稍后重试`，稍后再点一次即可。

## 通知

评论、状态变更与指派会同时触发两类通知。

### 邮件通知

发送条件全部满足时才会发信：站点开启「发送议题邮件通知」、SMTP 配置可用、收件人开启了「接收议题邮件通知」、且操作者不是收件人本人。

- 评论：发给议题作者。
- 状态变更：发给议题作者，正文包含旧状态与新状态。
- 指派：发给新增加的受理人。
- 邮件标题、正文与「查看议题」「退订」链接都使用平台默认语言，链接基于站点地址生成；每封邮件带有个人退订令牌，点击后关闭该账户的全部议题邮件通知（`receiveEmailNotifications = false`）。
- 发信失败不会影响评论或状态变更本身，也不会重投。

### 游戏内通知

在线服务器通过 WebSocket 收到实时事件：

- `ticket:comment_created`：新评论，消息里带议题标题、作者名与截断后的评论内容。
- `ticket:status_changed`：状态变更，消息里带变更前后的状态与操作者名称。

事件按玩家 UUID 定向推送：议题作者与全部受理人中，只有已绑定 Minecraft 且在线的玩家会收到；操作者本人不会收到自己触发的通知。议题若属于某台来源服务器，事件只推给该服务器；否则推给全部已连接的服务器。通知以聊天栏消息呈现，整行可点击，效果等同执行 `/lit ticket info <id>`；收到事件后插件会刷新本地缓存，让 `/lit ticket list` 立刻看到变化。

## 附件

### 允许的类型与大小

上传时同时校验声明类型与文件头（magic bytes），不匹配会报 `文件内容与声明类型不匹配`：

| MIME 类型 | 文件头校验 | 浏览器展示方式 |
| --- | --- | --- |
| `image/png` | `89 50 4E 47` | 内联（inline） |
| `image/jpeg` | `FF D8 FF` | 内联（inline） |
| `image/gif` | `47 49 46 38` | 内联（inline） |
| `image/webp` | `52 49 46 46` | 内联（inline） |
| `application/pdf` | `25 50 44 46` | 下载（attachment） |
| `text/plain` | 无（仅按声明类型判断） | 下载（attachment） |

单文件大小上限固定为 10 MiB，超出会被拒绝。前端只开放上述六种类型拖拽与粘贴，其它类型会被过滤掉。

### pending 生命周期与配额

上传接口为 `POST /api/attachments/upload`，可以带 `ticketId` 或 `commentId`（二者不能同时提供）：

- 不带目标时文件先进入 `pending` 状态，等待创建议题或发表评论时被认领；认领要求文件属于当前用户、状态仍是 `pending` 且未过期。
- pending 配额默认 50 MiB（按用户累计，只统计未过期未关联的附件），超出返回 `待关联附件已达到配额，请先完成议题或删除未使用的附件`。
- pending 默认启用过期，有效期 7 天；到期后既不能被认领，也无法下载。
- 后台清理任务每 15 分钟回收一次过期的孤立附件，并删除其存储文件。
- 预置目标上传（带 `ticketId` / `commentId`）会直接进入 `attached` 状态并不过期，但要求上传者是议题作者或评论作者（或管理组），否则分别报 `只有议题作者或管理组可以向该议题上传附件` 与 `只有评论作者或管理组可以向该评论上传附件`。

### 下载与删除

- 下载 `GET /api/attachments/:id` 受可见性约束：挂在议题或评论上的附件要求访问者能看见该议题；尚未关联的附件只有上传者本人与 admin 能取到。
- 处于清理中状态或已过期的 pending 附件一律返回「附件不存在」。
- 删除 `DELETE /api/attachments/:id`：只有上传者本人或 admin 可以删除（`只能删除自己上传的附件`），staff 也不能删他人附件。
- 存储位置由后台「存储」页决定（本地目录或 S3 兼容对象存储）。附件记录会保留上传时使用的存储类型，切换驱动后新旧附件各按自己的类型读取；但改动本地目录或 S3 桶配置会影响所有同类型附件。
