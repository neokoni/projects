# 评论与附件

## 发表评论

议题详情页底部设有评论框。内容填写完毕后点击「发表评论」。评论框同样支持 Markdown，并支持直接粘贴或拖拽图片。

评论框旁边另设有以下按钮：

- 「评论并关闭」：发表评论并关闭议题；
- 「评论并关闭（标记无效）」：发表评论并将议题标为无效（仅对管理组显示）；
- 「评论并重新打开」：发表评论并重新打开议题。

在游戏内提交的评论，时间线上将带有 `MC` 标记。

## 支持的格式

正文与评论使用同一套渲染规则：

| 语法 | 显示效果 |
| --- | --- |
| 标题、段落、加粗、斜体、删除线 | 支持 |
| 有序、无序列表 | 支持 |
| 任务列表（`- [x]`） | 显示为勾选框，但仅作展示，无法点击 |
| 表格 | 支持 |
| 代码块与行内代码 | 支持，代码块右上角设有复制按钮（不提供语法高亮） |
| 图片 | 支持，可直接粘贴上传或使用图片链接 |
| 链接 | 支持，裸链接将被自动识别，并在新标签页中打开 |
| HTML 标签 | 不支持，将作为普通文字显示 |

换行按输入的行数原样保留，输入几行即显示几行。

## 引用回复

在评论上使用「引用回复」时，被回复的内容将以引用块插入编辑框，在其下方继续编辑即可。

游戏内的写法为 `/lit ticket comment <编号> reply <序号>`，序号从 `0` 开始，即列表中的第一条为 `0`。

## 编辑与删除

| 操作 | 可执行者 |
| --- | --- |
| 编辑评论内容 | 仅评论作者本人 |
| 删除评论 | 评论作者本人，或管理组 |

管理组可删除他人的评论，但不得修改他人的评论。编辑过的评论将在时间线上显示为「编辑了评论」，并可展开查看修改前后的内容。删除评论时，该评论下的附件将一并清理。

## 通知渠道与触发条件

评论、状态变更、被指派均会产生提醒，分两种渠道。

### 邮件

邮件仅在同时满足以下条件时发出：站点已开启议题邮件通知、站点已配置发信服务、收件人已开启「接收议题邮件通知」，且操作者不是收件人本人。

- 有新评论：发送给议题作者；
- 状态变更：发送给议题作者，信中写明变更前后的状态；
- 被指派：发送给新增的受理人。

每封邮件底部均设有退订链接（对应 `/unsubscribe`），点击一次即关闭该账户的全部议题邮件提醒。

发信失败不影响评论与状态本身，也不补发。

### 游戏内

已绑定 Minecraft 且在线的用户，其聊天栏将收到提醒：

- 有新评论：显示议题标题、评论人及部分内容；
- 状态变更：显示议题标题、变更前后的状态及操作人。

同一议题仅作者与被指派者会收到通知；用户自身操作触发的通知不会发送给本人。整行提醒可点击，效果等同于执行 `/lit ticket info <编号>`，进入详情页。

## 附件

### 可上传的格式

| 格式 | 页面显示方式 |
| --- | --- |
| PNG、JPEG、GIF、WebP | 直接显示为图片 |
| PDF、纯文本 | 显示为下载链接 |

单个文件最大 10 MiB。上传时将校验文件内容与格式是否一致，扩展名与内容不符的文件将被拒绝。

### 账户附件配额

先上传、后使用的文件将先占用一个临时位置：

- 每个账户最多可保留 50 MiB 未使用的附件；达到上限后，须先提交议题或评论，或删除未使用的附件；
- 临时附件将在 7 天后过期，过期后既无法使用也无法下载；
- 站点将定期清理过期的临时文件。

### 附件的可见性与删除权限

挂在议题或评论上的附件，其可见性与议题一致：可查看议题即可下载附件。

删除仅能由上传者本人或管理员执行，管理组（非管理员）不得删除他人上传的附件。

附件的实际存储位置（服务器本地目录或对象存储）由管理员在后台「存储」页设定；切换后，新上传的文件将存入新位置，旧文件仍可正常打开。
