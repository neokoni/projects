# 新增语言

## 语言文件创建

1. 在 `data/locales/` 下新建 `<语言ID>.json`。
2. 配置 `manifest`（该语言的显示名称与文字排版方向）与 `messages`（文案条目）。
3. 刷新页面；该语言将出现在「个人资料 → 语言」的语言选择器中。

## 语言 ID

语言 ID 取自文件名（去掉 `.json` 后缀），`ja-JP.json` 的 ID 为 `ja-JP`。该 ID 同时作为语言选择器的存储值，并写入用户的浏览器偏好；ID 确定后不得修改。

文件名仅允许字母、数字、下划线与短横线（如 `ja-JP`、`zh-TW`、`pt_BR`），且须以 `.json` 结尾；文件名含 `.properties.` 的文件将被跳过。

## manifest

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `displayName` | 是 | 语言选择器中显示的名称。缺失或为空时，整份文件将被跳过 |
| `direction` | 否 | `ltr`（默认）或 `rtl`；`rtl` 使整个界面从右至左排版 |

## messages

`messages` 采用嵌套写法，读取时将转换为点号键：

| 文件中的写法 | 读取后的键 |
| --- | --- |
| `{ "common": { "save": "保存" } }` | `common.save` |

写法约定：

- 值须为字符串；数字、布尔值与数组将被忽略。
- 一个节点既有自身文案又有子项时，自身文案挂于保留键 `self` 下。

```jsonc
"hookEvent": {
  "self": "触发事件",
  "closed": "议题关闭"
}
```

读取后为 `hookEvent` 与 `hookEvent.closed` 两条，不会互相覆盖。

## 最小实例

```jsonc
{
  "manifest": {
    "displayName": "日本語",
    "direction": "ltr"
  },
  "messages": {
    "common": {
      "save": "保存する",
      "cancel": "キャンセル"
    },
    "ticket": {
      "status": {
        "open": "対応待ち"
      }
    }
  }
}
```

保存并刷新页面后，语言选择器中将出现「日本語」。语言选择器按 ID 排序，与添加顺序无关。

## 缺失的键

未写的键将回退到简体中文，回退目标为内置的 `zh-CN`，而非平台默认语言。因此可先仅翻译常用条目，其余位置仍显示中文，不会出现空白或直接显示键名的情况。

查询某条文案对应的键名时，在 `backend/src/locales/zh-CN.json` 中按原文搜索即可；同一键在 `en-US.json` 中提供英文对照。

## 翻译注意

- 文案中的 `{name}`、`{count}` 等占位符须原样保留，位置可按语言习惯调整。
- 建议标点与全半角跟随目标语言，不使用中文引号「」。
- 建议同一语言内的术语保持一致，例如 `ticket` 统一译为同一个词，不在列表页与详情页使用两种说法。
