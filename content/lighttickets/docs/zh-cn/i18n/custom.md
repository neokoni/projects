# 新增语言

## 新建步骤

1. 在 `data/locales/` 下新建 `<语言ID>.json`；
2. 写 `manifest`（这门语言叫什么、朝哪个方向排）与 `messages`（一条条文案）；
3. 刷新页面，到「个人资料 → 语言」里就能选到它。

## 语言 ID

语言 ID 取自文件名（去掉 `.json` 后缀），`ja-JP.json` 的 ID 就是 `ja-JP`。这个 ID 是语言下拉里的取值，也会记在浏览器偏好里，定下来之后不要改。

文件名只允许字母、数字、下划线与短横线，例如 `ja-JP`、`zh-TW`、`pt_BR`，并且必须以 `.json` 结尾；名字里带 `.properties.` 的文件会被跳过。

## manifest

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `displayName` | 是 | 语言下拉框里显示的名字。缺失或为空会让整份文件被跳过 |
| `nativeName` | 否 | 这门语言自己的写法，留空则沿用内置值 |
| `direction` | 否 | `ltr`（默认）或 `rtl`；`rtl` 会让整个界面从右往左排 |

## messages

嵌套写法，读取时会压成点号键：

| 文件里写的 | 读出来的键 |
| --- | --- |
| `{ "common": { "save": "保存" } }` | `common.save` |

写法约定：

- 值必须是字符串，数字、布尔、数组都会被忽略；
- 一个节点既有自己的文案、下面又有子项时，自己的文案挂在保留键 `self` 下：

```json
"hookEvent": { "self": "触发事件", "closed": "议题关闭" }
```

读出来是 `hookEvent` 与 `hookEvent.closed` 两条，不会互相覆盖。

## 最小实例

```json
{
  "manifest": {
    "displayName": "日本語",
    "nativeName": "日本語",
    "direction": "ltr"
  },
  "messages": {
    "common": {
      "save": "保存する",
      "cancel": "キャンセル"
    },
    "ticket": {
      "status": {
        "open": "対応待ち"
      }
    }
  }
}
```

保存后刷新页面，语言下拉里就会出现「日本語」。下拉是按 ID 排序的，与添加顺序无关。

## 缺失的键

没写的键会回退到简体中文：回退目标是内置的 `zh-CN`，而不是平台默认语言。所以可以先只翻常用的几条，其余位置仍显示中文，不会出现空白或裸键名。

想知道某条文案对应的键名，在 `backend/src/locales/zh-CN.json` 里按原文搜一下即可；同一个键在 `en-US.json` 里有英文对照。

## 翻译注意

- 文案里的 `{name}`、`{count}` 这类占位符要原样保留，位置可以按语言习惯调整；
- 标点与全半角跟着目标语言走，别沿用中文的「」；
- 术语在一门语言里保持一致，例如 `ticket` 统一译成同一个词，别在列表页和详情页用两种说法。
