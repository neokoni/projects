# 覆盖内置文案

仅需修改少量文案时，无需整份重写：将一个同 ID 的文件放入 `data/locales/`，该文件将覆盖内置语言文件。

## 操作步骤

1. 在 `data/locales/` 下建立与内置同 ID 的文件，例如 `zh-CN.json`；
2. 文件中仅写入需修改的键；
3. `manifest` 仍须提供，至少包含 `displayName`。

每份语言文件均须包含 `displayName`。仅写入 `messages` 的文件将被整份跳过，日志中打印一条警告，界面显示无变化。

## 合并规则

| 内容 | 合并方式 |
| --- | --- |
| `messages` | 按扁平化后的键逐条覆盖；未写入的键沿用内置文件 |
| `manifest` | 按字段覆盖；未写入的字段沿用内置内容 |

建议文件中的键与内置文件完全一致（点号路径）。键名写错不产生错误，仅新增一条无引用的键，原句照旧显示。修改完成后刷新页面确认。

## 示例

示例仅将「保存」改为「提交」，并修改状态名称：

```json
{
  "manifest": {
    "displayName": "简体中文"
  },
  "messages": {
    "common": {
      "save": "提交"
    },
    "ticket": {
      "status": {
        "open": "待处理",
        "in_progress": "处理中"
      }
    }
  }
}
```

未覆盖的文案仍来自内置文件，升级时随之更新。

## 适用场景

- 术语与团队习惯不一致，例如将「议题」统一称为「工单」；
- 某句说明过长，需替换为更短表述；
- 内置措辞有误或不符合场景时，可在本地修改，无需等待上游更新。

## 注意事项

- 升级后内置新增的键将自动出现，但其内容仍为内置语言的原文；如需译为其他语言，建议另行补充。
- 长期维护一整门语言时，整份复制后修改，其代价为：内置文件之后的修正不再进入该语言文件。
- JSON 须合法。格式错误的文件将被跳过，并在日志中打印一条 `[i18n] skipping custom language ...`，界面回退到内置文案。
- 如需恢复原样，删除 `data/locales/` 中的该文件，无需修改任何配置。

## 键名查找

内置文件为嵌套结构，实际使用点号路径。如需修改议题关闭时通知邮件的措辞，先在 `backend/src/locales/zh-CN.json` 中按原文搜索到对应位置，再将节点路径依次连接为 `mail.xxx.yyy` 并写入覆盖文件。英文原文见 `en-US.json`，两边的键一一对应。
