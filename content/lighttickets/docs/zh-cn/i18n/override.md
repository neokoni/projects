# 覆盖内置文案

只想改几条措辞时，不用整份重写：放一个同 ID 的文件到 `data/locales/`，它会盖在内置语言上。

## 操作步骤

1. 在 `data/locales/` 下建一个与内置同 ID 的文件，例如 `zh-CN.json`；
2. 里面只写要改的键；
3. `manifest` 仍然要给，至少写 `displayName`。

第 3 步容易漏：每份语言文件都要有 `displayName`，只写 `messages` 的文件会被整份跳过，日志里留一条警告，界面看起来「什么都没变」。

## 合并规则

| 内容 | 怎么合并 |
| --- | --- |
| `messages` | 按扁平后的键逐条覆盖；没写的键继续用内置那份 |
| `manifest` | 按字段覆盖；没写的字段沿用内置 |

所以文件里的键要和内置完全一致（点号路径）。键名写错不会报错，只会多出一条没人引用的键，原句照旧显示——改完记得刷新确认。

## 示例

只把「保存」改成「提交」，把状态叫法改掉：

```json
{
  "manifest": {
    "displayName": "简体中文"
  },
  "messages": {
    "common": {
      "save": "提交"
    },
    "ticket": {
      "status": {
        "open": "待处理",
        "in_progress": "处理中"
      }
    }
  }
}
```

其余七百多条继续来自内置文件，升级时也会跟着更新。

## 适用场景

- 术语与团队习惯不一致，比如把「议题」统一叫「工单」；
- 某句解释太长，想换成更短的说法；
- 内置措辞有误或不合场景，先本地改掉，不必等上游。

## 注意事项

- 升级后内置新增的键会自动出现，但仍是内置语言的原文；要翻成别的语言得自己补。
- 想长期维护一整门语言，整份复制出来改会更省事；代价是内置之后的修正不会再进入你的文件。
- JSON 必须合法。写坏的文件会被跳过并在日志里记一条 `[i18n] skipping custom language ...`，界面退回内置文案。
- 想恢复原样，把 `data/locales/` 里那份文件删掉即可，不用改任何配置。

## 查找要改的键

内置文件是嵌套结构，实际用的是点号路径。比如要改议题关闭时的通知邮件措辞，先在 `backend/src/locales/zh-CN.json` 里按原文搜到位置，再把节点路径拼成 `mail.xxx.yyy` 写进覆盖文件。英文原文看 `en-US.json`，两边的键一一对应。
